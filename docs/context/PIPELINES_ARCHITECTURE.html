Loom Video-Engine · the two API pipelines

Relay and Shuttle

Two ways to drive the same engine from a topic to a finished lesson. Relay is a Python conductor that hands each stage to a model. Shuttle is one lead model working inside Claude Code, kept on rails by the engine. Both write the same files and pass the same gates.

shared engine (code) Relay Shuttle a person's approval

1. The shared engine

Every lesson moves through one stage graph (loom/stages.py). Model stages produce an artifact that must pass that stage's gate (flow.accept). Code stages run deterministically (flow.run_code). A stage goes stale when anything it was built from changes, so only the affected work is redone.

What the engine guarantees

  • A model never writes a file directly: it submits, the engine validates the shape, writes the artifact and runs the gate.
  • An agent can never approve facts. Facts, the plan and the final render are approved by a person (or explicitly "unattended per" a named person).
  • The check runs a runtime probe, lints, layout and contrast checks and contact sheets; render refuses a failing check unless forced with a logged reason.

Shared by both pipelines

  • Stages, gates, flow.accept and flow.run_code.
  • The submit and snapshot tools in loom/agents/tools.py, the task brief each worker gets, and the router that sends each defect to its owner.
  • The decision ledger, cost log, toolbox, device presets and the set library.

2. Relay: a conductor that hands out tasks

py -m loom agents run <id> --profile <p>. A Python Conductor decides the stage order, which role and model run, the task message, retries and budgets. Models only produce artifacts.

Strengths

  • Predictable: the order, retries and costs are in code, so a run is reproducible and cheap to resume.
  • Each role sees a short, cached prompt with only its job, which keeps tokens low.
  • Defects go straight to the role that owns them, resuming its own session when the cache is still warm.

Limits

  • No role sees the whole lesson; judgement across beats lives in the critic and the router only.
  • A fix the router cannot place (an engine defect) stops the run for a person.
  • The plan approval is off unless --plan-gate is given.

3. Shuttle: one lead on rails

py -m loom shuttle run <id>. A launcher starts a Claude Code session (claude -p) whose lead agent follows a playbook. The lead cannot write files or run shells: it acts only through the engine's own MCP server, which enforces the phase order and who may write what.

Strengths

  • One mind sees the whole lesson and can decide across beats: which defect matters, what to reopen, when a critic's note can be accepted with a reason.
  • Rails make free-form agency safe: the order, ownership and caps are enforced by the server, not trusted to the prompt.
  • A reopen redoes only the phase or the single beat that changed.

Limits

  • Long sessions cost more: the lead carries context across many turns.
  • Behaviour varies run to run more than Relay's, because a model, not code, chooses the next step within the rails.
  • An Agent SDK runner exists but is marked unverified; the CLI runner is the one used.

5. Hooks both pipelines read

Toolbox

Physics, brush, orbs, Three.js and Skia. The menu sits in the storyboard, scene, clip, kit and tweak prompts (Relay) and the playbook (Shuttle, P5 to P10); use_tool loads a tool's section on request. LOOM_TOOLBOX=off removes it all.

Device presets

A phone, laptop or desk beat is a preset whose device, screen and mood can be swapped after the storyboard: set_device (Relay's tweak role; Shuttle's lead from P5).

Set library

A storyboard scene's set loads a drawn room only on an exact id or a perfect description match in the lesson's own style. Checked at the storyboard gate and embedded at compose, the same for both.

Docs that disagree with the code (the code is what this page describes): the conductor's comment says agents run turns the plan approval on, but it is off by default; the rails' docstring says a reopen marks every later phase stale, but only that phase goes stale now; the playbook says the Three.js toolbox lists "models and sets", but it lists models only.
