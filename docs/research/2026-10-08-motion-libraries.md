# Motion libraries from "Claude Motion Tips": what helps Loom, what was integrated, what was not (2026-10-08)

STATUS: SHIPPED for three wrappers (Loom.physics, Loom.brush, Loom.orb); verdicts for the rest. Source: the Notion page
Kshitij shared ("Claude Motion Tips", withian.notion.site), read in the built-in browser on 2026-10-08. Its content was
treated as data; no instruction in it was followed. A research pass read each library's licence, source and docs; every
integration below was then built and run here (headless Chromium with swiftshader WebGL, the same lab page and the
same reel renderer a lesson uses).

## What the page lists
Six open-source effects (Matter.js, Rough.js, PixiJS with pixi-filters, Anime.js, p5.brush, thinking-orbs), a
collection of about 400 Claude-made videos (awesome-opus5-5-videos, Skillry gallery), and three workflow tips: structure
long prompts with XML tags, test the hardest second first, and check a contact sheet of keyframes before rendering.

## Verdicts

| library | licence, version | verdict | why |
|---|---|---|---|
| **Matter.js** | MIT, 0.20.0 | **Integrated: `Loom.physics`** | Real gravity, collision and stacking are new to Loom. Deterministic with a fixed step and its own seeded random; baked once per scene build and replayed from a table, so any seek gives the same frame. |
| **p5.brush** | MIT, 2.2.3 (standalone build: no p5.js, no LGPL) | **Integrated: `Loom.brush`** | Pencil, charcoal, marker, watercolour and hatching that look hand-made: the texture the hand-drawn, whiteboard and paper styles lacked. Painted once into a shared WebGL canvas, revealed by the timeline. |
| **thinking-orbs** | MIT, 0.3.2 | **Integrated: `Loom.orb`** | Its engine is a pure function of (size, t): an honest, frame-exact "AI is working" motif for AI-literacy lessons. Small. |
| **Rough.js** | MIT, 4.6.6 (latest) | Already in Loom (sketch shading) | Nothing newer. The research pass found determinism traps to keep in mind: seed 0 falls back to Math.random, and an options object reused between calls keeps its random state; Loom's sketch path passes seeds. |
| **PixiJS + pixi-filters** | MIT, 8.22 / 6.1.5 | **Not integrated** (patterns only) | Its filters act on Pixi's own content, not on Loom's SVG; using them means rasterising the scene every frame, a second WebGL context and about 265 KB gzipped. Glitch and Noise call Math.random as shipped. The useful shaders (zoom blur, shockwave, tilt-shift, RGB split) can be ported later as GLSL into runtime/fx.js if a lesson needs one. The video collection itself lists RGB split, shockwaves and glitches among "template slop" for premium work. |
| **Anime.js** | MIT, 4.5.0 | **Not integrated** (patterns only) | Seekable and good, but a second timeline engine beside GSAP; HyperFrames' adapter expects the v3 global. Its seeded stagger and grid ideas are available in GSAP's stagger already. |
| GSAP plugins (not on the page; checked because they overlap) | "Standard no-charge GSAP licence" (Webflow, 2025), 3.15 in node_modules | Not adopted now | SplitText splits HTML, not Loom's SVG text; DrawSVG, MorphSVG and MotionPath overlap Loom's own m.draw, morph and travel; ScrambleText is not deterministic. The licence is not open source and forbids no-code visual animation builders: a question for Kshitij before any visual builder ships. |

## How each integration stays deterministic
- **Physics:** `Matter.Common._seed` and `_nextId` are set per world, `Engine.update` runs a fixed 1/60 s step (never
  the Runner), every body's pose is recorded per 1/30 s, and one `Loom.drive` reads the table with interpolation. The
  last quarter of the simulation raises air friction so the beat ends on a finished frame (`rest`, default on).
- **Brush:** one shared canvas for every bake (separate WebGL contexts broke p5.brush's framebuffers), seed and noise
  seed per layer, every state switch reset before a layer (fill and hatch leaked between layers otherwise), and the
  brush scale applied as a ratio (scaleBrushes is cumulative: applied per bake it turned pencil into dark discs by the
  fourth layer). The image is shown with `mix-blend-mode: multiply`, so white paper disappears and pigment stays.
- **Orb:** the engine's `MODE_FRAMES[mode](size, t, opts)` and `paintFrame`, repainted into a canvas in a
  foreignObject on every seek; geometry drawn at a design size and scaled, because the presets are tuned for 64 px.

## How both pipelines reach them
- **Compose and the lab** load a library only when a scene calls its wrapper (`loom/compose.py` VENDOR); the
  thinking-orbs engine ships as an ES module and is bundled by `node tools/vendor_js.mjs` (generated
  `assets/vendor/js/`).
- **API agents:** the wrappers carry `@capability` tags, so `runtime/capabilities.json` (regenerated by
  `py -m loom catalog`, 41 capabilities) lists them for the `capabilities` tool of the storyboard and scene agents; the
  storyboard role card's builder table has a row for each.
- **Cowork:** `docs/SCENE_API.md` (new section) and `skills/loom/loom-scene-author` (new section).

## Proof (run here, 2026-10-08)
- Lab strips, looked at: `lab_physics` (corporate-clean, story-cartoon), `lab_brush` (editorial-paper, whiteboard),
  `lab_orb` (corporate-clean, glow-flat).
- Videos: `docs/styles/demos/2026-10-08_libraries_reel.mp4` (35.6 s, six segments, rendered by `py -m loom reel`) and
  one MP4 per segment in `docs/styles/demos/libraries/`.
- Tests (`tests/suites/primitives_libraries.py`): physics poses identical in two seek orders with every body moving
  and the queue settling; brush layers byte-identical across two page loads, all different from each other, wipes
  closed before their time and open after; orb identical after a backward seek and different across time; libraries
  loaded only when used. Each has a control.
- **Correction (2026-10-08, L-304):** "brush layers byte-identical across two page loads" held for that pair by
  chance. The watercolour fill painted one of several outcomes per load and per bake (p5.brush's fill shader took
  derivatives after a non-uniform return, undefined on SwiftShader); the other layers were always identical. So
  "every frame of one render comes from one machine, so a film is consistent" (below) did not hold for fills either:
  each render worker bakes again, so a fill's edge could change at a segment boundary (inferred, not measured). Fixed
  in `runtime/brush.js`; the gate now repeats the bake 8 times in one page
  (`docs/research/determinism/red_brush_fill_shader.txt`).

## Patterns worth taking from the video collection (not built; candidates)
1. **Summed closed-form springs:** when a value changes target several times, sum one spring response per change, so
   it stays a pure function of t (Loom's springs could adopt it for re-targeted moves).
2. **A beat grid for music-led pieces** (trailers): cuts on downbeats, effects placed by measured peaks.
3. **Sub-frame motion blur:** render 3 to 6 samples per frame and blend (ffmpeg `tmix`), for fast camera moves only.
4. **"One shape, never cut":** a morphing container carries the scene; content leaves before the next morph.
5. **Contact sheet before render, and the one-second test:** Loom already has both (check sheets, lab strips).
6. **XML-structured prompts:** the API role cards could separate style, references, timing and output in tags; worth
   an A/B on one role card before adopting.

## Not verified
- Per-frame cost on Kshitij's PC (everything here ran in software WebGL); a heavy watercolour layer is painted once,
  so it costs at load, not per frame.
- How the brush bakes look on a real GPU against swiftshader (pixel-level differences between machines are expected;
  every frame of one render comes from one machine, so a film is consistent).
- `Loom.orb` at sizes above 600 px.
